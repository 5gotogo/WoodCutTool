# Whole-site LCP and Responsiveness Audit — 2026-09-08

## Outcome

The site now assigns each generated page to a performance profile instead of shipping the complete authored stylesheet and calculator runtime everywhere. A 16-route mobile sample, covering the main page families, completed with median LCP between 548 ms and 728 ms under the local throttled test. All sampled pages reported CLS 0 and no horizontal overflow at 390 px.

The local test uses a gzip preview, a 390 × 844 viewport, cold cache, 4× CPU throttling, 150 ms latency, and 200 KB/s download throughput. These are synthetic development results, not production Chrome UX Report data.

## Main causes removed

- Static content pages no longer download the 289 KB authored `app.js`; only 19 genuinely interactive routes retain it, while two stair routes use their dedicated 9 KB calculator bundle.
- Generated pages no longer serve the 230 KB authored `styles.css`. They use scoped generated CSS for App, editorial, content, or interactive pages.
- The Blog index no longer embeds more than one thousand directory records in its initial HTML. Its full crawlable list is at `/blog/archive/`, while browser search loads a compact index only after search intent.
- Blog translations are route-level payloads and only load for Simplified or Traditional Chinese. The former 8.9 MB monolithic payload is no longer published.
- Learn directory cards no longer trigger 12 decorative full-size woodworking images from CSS.
- Blog card images use lazy responsive `<img>` elements; article, Learn, Compare, Tools, and Project hero images use responsive candidates and priority preloads where applicable.
- Shared navigation constructs mega-menu contents only when a menu opens. The header uses an 894-byte WebP brand icon, scroll handling is animation-frame throttled, and mobile backdrop blur is disabled.
- Long directory sections use `content-visibility` to avoid unnecessary off-screen layout and paint work.
- Redirect and standalone pages do not load site chrome, conversion tracking, CSS, or application runtimes.

## Regression protection and QA

- `npm run audit:performance` runs the repeatable browser performance harness. It accepts `--origin`, `--cdp-port`, `--runs`, `--routes`, and `--output`.
- `npm run test:core-web-vitals` checks scoped CSS freshness and budgets, lightweight runtimes, responsive article images, hero preloads, Blog payload budgets, and compact shared assets.
- `npm run check` validates 2,471 HTML files, all sitemap/indexability/SEO/architecture rules, conversion integration, and critical workflows.
- The real browser P1 suite passed at 360, 390, 430, and 1,440 px, including overflow, navigation, keyboard submission, template import, export, and lazy language-runtime checks.

## Production follow-up

After deployment, compare Cloudflare Web Analytics or another field-data source by route family at p75, p90, and p99. The production acceptance target should be p75 LCP at or below 2.5 seconds with stable CLS and interaction latency. Synthetic local measurements cannot confirm CDN, device mix, third-party App Store assets, or real-user network tails.
