# WoodCutTool 下周功能计划

规划日期：2026-09-05。执行窗口：2026-09-07 至 2026-09-13。

## 建议

本周主目标：让访问者从一个项目示例进入计算器、得到结果、带走清单，并能够观察各步骤的聚合使用情况。以书架、车库层架、基础柜体三个场景试点。按一名开发者约五个工作日安排，周末用于观察与复盘。

## 优先级与交付

### P0：转化数据可以持续比较（周一，约 1 天）

现状：转化端点校验事件后写 `console.log`，未在该接口中实现持久化聚合。生产环境可能另配日志接收端，本次尚未核实。`wrangler.toml` 中 Apple provider token 为空，生产环境变量是否覆盖也需核实。

- 查明现有日志保留、接收和查询能力；有可用后端就复用，否则增加按日聚合的存储与导出。
- 固定日报字段：日期、页面/场景、事件、设备类别、事件次数；不记录尺寸、零件名、项目正文或用户标识。
- 覆盖示例打开、带入计算器、计算完成、清单导出和 App Store 跳转；先核查现有注册事件与触发器，只补缺失部分。
- 输出一个可复用的聚合日报查询或导出脚本，报告工具完成率、导出事件/计算完成事件、App 跳转事件/对应 CTA 展示事件。
- 没有会话或用户标识时，只称事件比率，不称唯一用户漏斗或安装转化率；重算、重复点击和 DNT 会影响解释。

验收：一条受控测试流程可在聚合结果中核对；重复触发行为有明确口径；DNT 生效；无项目数据上传。缺少生产访问时完成本地验证和待部署材料，将生产验证明确标记为待办。

### P0：三个场景的“用此清单计算”（周二至周三，约 2 天）

现状：示例页目前说明用户替换清单尺寸后到计算器重新输入；单板收藏、项目进度和组件项目分别有自己的本地状态。已有保存功能应复用，不重新创建一套项目管理系统。

- 示例/组件页增加“用此清单计算”，将零件、数量、单位、板材分组及适用的排版约束带入计算器。
- 首期只支持三个明确场景以及计算器实际支持的输入；不支持的约束必须在继续前可见，不可静默丢弃。
- 采用浏览器本地暂存和版本化载荷，不把完整项目内容塞进查询参数。
- 结果页提供明确下一步：调整、导出已有格式、打印适用摘要、查看相关施工检查或 CutList 功能。
- 保留用户已有输入；冲突时允许明确选择，禁止自动覆盖。

验收：三个场景分别完成“打开示例 → 带入 → 调整 → 计算 → 导出”；检查英制/公制、数量展开、材料厚度分组、超大零件、无效值与本地存储不可用的情况。不可完成的布局必须清楚标记。若主计算器需要大规模输入模型重构，首期缩到一个完整场景，确保其余场景不显示虚假的一键能力。

### P1：让入口与移动端服务于完整流程（周四，约 1 天）

- 复用首页已有“按项目开始”和工具选择入口，优先展示三个试点，不新增一整套导航。
- 每个试点页面明确一个主行动，结果后再给上下文相关的资料和 App 入口。
- 检查首页演示中的节省金额、板数和浪费比例是否来自当前输入；演示数值应明确标注，避免被理解为用户真实结果。
- 核验 360/390/430px 下表单、结果、表格、键盘输入、下载和菜单；桌面做一轮冒烟检查。

验收：没有页面级横向溢出；主操作可发现；重要错误无需滚动查找；演示与真实计算的文案清晰。

### P1：性能、内容与发布验收（周五，约 1 天）

- 确认近期 App 轻量资源已在线上生效；按页面组、设备、地区和样本量比较部署前后的 RUM。
- 优先检查首页、胶合板计算器与试点页；若发现长任务或慢资源，集中修复一个影响最大的瓶颈。
- 有 Search Console 聚合数据时，选择与试点相关、存在曝光机会的 5 个已有页面改善标题、开头回答和行动链接；没有数据时按流程相关性选页，不声称其为流量最高页面。
- 执行生成器及必要后处理、`npm run check`、`git diff --check` 和代表页面浏览器 QA。

验收：无结构、单位、隐私或布局回归；保留部署时间与验证记录。LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 作为真实用户 P75 目标，样本不足时只报告观察，不宣称达标。

### 周末：观察与复盘

- 检查事件持续进入、错误与导出失败、主要设备上的反馈。
- 输出完成项、遗留项、事件次数和样本限制；下一轮选择扩展场景或先修复流程问题。
- 搜索效果保留改动前 28 天基线，在改动后的完整 28 天窗口复查，不以周末几天的波动判断 SEO 成败。

## 本周不纳入承诺

- 大批新增博客、对比页或全新栏目：先验证现有内容能否帮助完成操作。
- 统一全站搜索：有价值，但本周优先修复已进入页面后的使用流程；后续依据找不到工具的证据安排。
- 登录、云同步、多人协作：会扩大当前浏览器本地功能的边界。
- 将 8 个 Research 报告一次扩到 15 个：后续每批做 1–2 个可复现报告，明确方法与限制。
- 无搜索查询证据的批量合并、重定向或 noindex。

若周中进度超出预算，先减少精修页数和入口美化，保留数据闭环、至少一个端到端场景及必要验证。
